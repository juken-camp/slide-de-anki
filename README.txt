卑弥呼と受験対策：偉人からのメッセージ／日付・時刻・既読

今回のファイルを既存プロジェクトへ配置し、依存関係をインストールしてデプロイします。
初期設定はオフです。通常の個人・グループチャットは従来のAPI設定で動作します。

含むもの
・index.html：GitHub juken-camp/slide-de-anki の main から取得した本体に、外部連携スクリプト1つを追加したもの。
・himiko.html：個人・グループの日付、時刻、既読、自動受信、未読件数。
・himiko-activity.js：設定スイッチ、端末認証、実際の学習記録の概要の連携、PWAバッジ。
・himiko-push-sw.js：ホーム画面の通知とバッジ。
・api/himiko-chat.js、api/himiko-inbox.js、api/himiko-deliver.js、lib/himiko-inbox.js。
・package.json：web-push依存。既存のpackage.jsonがある場合はdependenciesを統合してください。
・vercel.json：既存のnekopon.js設定を維持し、配信関数の実行時間を追加。
・history-icons/group-chat.png：既存のグループアイコン。他の人物画像は既存のまま使います。

重要：これまでのファイル差し替えに加え、今回初めてサーバーの受信箱と定期実行が必要です。
このパッケージだけでは閉じている間の配信は開始しません。本番設定とデプロイはこの作業では実施していません。
設定が未完了の場合、設定画面はオンにせず、その旨を表示します。

設定手順
1. 既存のANTHROPIC_API_KEYとモデル設定を引き継ぐ。
2. Redis RESTストレージを用意し、UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN を設定。
   既存の KV_REST_API_URL / KV_REST_API_TOKEN でも利用できます。永続保存と定期処理で共用します。
3. npm install を実行。通知鍵は npx web-push generate-vapid-keys --json で生成。
   HIMIKO_VAPID_PUBLIC_KEY / HIMIKO_VAPID_PRIVATE_KEY にそれぞれ設定。
   HIMIKO_VAPID_SUBJECT は管理者の mailto:メールアドレス。
   CRON_SECRET は十分長いランダムな秘密文字列。
4. HIMIKO_INBOX_ENABLED=1 を設定。
5. 信頼できるスケジューラーから、1分ごとに以下をGETする。
   https://本番ドメイン/api/himiko-deliver
   Authorization: Bearer CRON_SECRETの値
   Vercelで毎分Cronが利用できる契約なら、vercel-cron-example.jsonのcronsをvercel.jsonに統合。
   Hobbyの1日1回ではランダムな時刻の配信を実現できません。外部の毎分スケジューラー等が必要です。
6. 実機で設定の「偉人からのメッセージ」をオンにする。
   ホーム画面の通知・件数も使う場合は、iPhoneのホーム画面に追加したアプリから通知許可を与える。
   件数のみを見せたい場合は、iPhone側の設定でバナー・ロック画面等をオフ、バッジをオンにする。
   アプリからOSの通知表示設定を強制変更することはできません。

動作
・配信時間は日本時間8〜22時。学習した問題数、改善した問題数、テスト完了数、操作中の学習時間、チャット回数の概要を使います。氏名・解答原文は連携しません。
・正解率ではなく取り組み量で頻度を増加。低活動でも最長48時間程度の間隔で機会を作ります。
・学習のない日の上限1回、取り組みのある日は最大3回、多い日は最大5回。時刻・内容は固定しません。
・自動会話1件の生成はAPI1回。自動配信には通常質問と別にAPI使用が発生します。
・未読でも追加されます。未読3会話分で新しい生成を休止し、読むと再開可能です。
・自動会話は生成時点から発言を5秒ずつずらして保存。スケジューラーと受信確認は分単位なので、閉じている間の通知到着に秒単位の保証はありません。
・アプリ内で会話中は生成を延期。自動会話の段階表示中も入力でき、割り込み時に未表示の続きを取り消します。
・未読は分割前の発言単位。チャットを開いただけでは消さず、最後のバブルが表示範囲に入った発言を既読にします。
・自動会話を受信するだけでは「話した人数」を増やしません。
・オフにすると今後の自動配信を停止。会話リセットでサーバーの配信待ちも消去。
・PWAプッシュの内容は実際の人物名と発言。「新しい会話が始まりました」の案内文は使いません。
・会話・受信箱は端末ごと。別端末との同期はありません。ブラウザーのデータ削除後は別端末扱いです。
・古い会話に元の日時がない場合は、架空の日付を付けません。新規の会話から記録します。

検証
サーバー生成、端末認証、初期オフ、未読処理、配信時刻、停止、リセット、入力検証、グループの日時・受信重複防止を模擬環境で確認。
本番スケジューラー、実際のClaude応答、iPhoneのPush/バッジ、スマホのレイアウトは実機確認が必要です。

追加点検・修正（2026/11/01）
・自動会話の生成を受信箱の更新処理から切り離し、生成中もオフ・リセットを受け付けます。
・生成中に取り消した会話が後から保存・配信されないことを確認しました。
・割り込みで未表示だった続きは、サーバーの未読件数からも取り消します。
・眺めているだけの状態では配信を抑制せず、実際のやり取り中に延期します。
・学習量の増加に合わせ、次回の会話生成予定自体を早められるよう修正。
・通知済み扱いになる前に読んだ発言を、後から再通知しないよう修正。
・端末からの更新要求を順番に処理し、一時的な更新競合を再試行。
・既読送信失敗時は再試行。長いバブルも末尾が見えれば既読にできます。
・iPhoneの通知許可は設定スイッチの操作直後に求める順序へ修正。
・今回も本番への反映、実際の通知・実機レイアウトの検証は未実施です。
