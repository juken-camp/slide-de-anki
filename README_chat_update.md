# 異次元グルチャ：会話の面白さ・歴史の話題分散アップデート

## 反映手順

1. ZIPを解凍する。
2. `api`、`lib`、`tests`を、GitHubの `slide-de-anki` の同じフォルダに重ねて追加・上書きする。フォルダごと削除・置換する操作は不要。
3. コミットし、Vercelのデプロイ完了を待つ。

**今回、新たなSQL実行・環境変数・外部サービスの登録はありません。**
先の世界観更新も含むため、このZIPでまとめて反映できます。既存の共有AI機能をまだ有効化していない場合、それを自動的に有効化する変更ではありません。

## 変更内容

- 5場面の自動会話を作る際、コード側で「歴史の話題3場面＋自由な雑談2場面」を選び、順番も混ぜる。
- 既存の歴史一問一答107問から、会話に使う87件を収録。問い・正答・元のカード番号を保持。特定の教科書を取得したものではない。
- 古代・平安・鎌倉／室町・戦国／江戸・明治・近現代・世界史の7区分から、同じバッチの歴史3場面は異なる区分にする。最近扱った区分の偏りも調整。
- 直近25場面にある用語と、同じ出来事を扱う関連用語を避ける。候補が足りない場合は古いものを優先。常に先頭や中央から選ぶ仕組みではない。
- 自慢、軽い張り合い、名称の混同、立場の違い、意外な細部への食いつきなど、会話の切り口も分散。全員の同意や称賛だけで終わらせない。
- 歴史3場面は指定用語が実際に登場するか検査。欠けた場面だけを除外し、別の場面へ誤って履歴を付けない。不正な場面がある場合、実際の配信数は5場面未満になることがある。
- 問いと正答を材料に、読んで意味や人物との関係がわかる掛け合いを生成するよう指定。毎回の小テスト・講義・教訓は必須にしない。
- 現代の学校での扱われ方について話せるが、実物の教科書のページ・掲載量・利用者の成績を見たふりはしない。
- くだけた現代語と人物間の敬意を維持。創作の感情・冗談を史実や本物の名言として語らず、戦争・差別・災害の犠牲を笑いの対象にしない。
- 別々の異次元から言葉だけでつながる世界観を共通適用。実際の待ち合わせや現実の住所をでっち上げない。

## 履歴と適用タイミング

- 一人用の自動グルチャ：既存の受信箱データに話題IDを保存。配信開始した場面だけ記録し、生成しただけ・破棄した場面は数えない。履歴は最大100場面。
- 共有グルチャの自動会話：既存Redisを利用し、部屋ごとに話題IDだけを保存。Supabaseが予約を受理したバッチだけ記録する。配信前に管理者がAIを停止しても、予約時の話題履歴は残る（重複回避を保守的に行うため）。人間の発言を新しくRedisへ保存する処理はない。
- 共有環境でRedisが未設定／一時的に使えない場合は、最近の発言に含まれる用語を参考に動作を継続。この場合、長期間にわたる話題分散は保証しない。既存の構成では設定追加は不要。
- 既存の表示済み会話は書き換えない。一人用の未配信ストックは次の処理時に旧バージョン分を破棄して新方針で生成する。共有側の予約済み会話は維持し、次の生成バッチから反映する。
- 手動の質問や個人チャットに「3＋2」の縛りは付けない。

## 費用・確認結果

AI呼び出しは従来どおり1回で5場面。ニュース取得のAPIは追加していない。指示と選んだ問答が入力に加わるため、トークン使用量が全く同じになるわけではない。共有側は1バッチにつきRedisの読み取り・書き込みが各1回追加される。

実行済み：

```sh
node --test tests/conversation-plan.test.cjs tests/shared-ai.test.cjs tests/worldview.test.cjs tests/api.test.cjs
```

33件成功。選定の分散、87件の元教材との一致、場面の検査、配信／予約と履歴の結びつき、既存認証・API境界、世界観の各生成経路への適用を確認した。AI応答はテスト用に置き換え、本物のAPIによる会話の品質・面白さや得点向上の効果は未検証。画面変更・データベース変更は行っていない。
