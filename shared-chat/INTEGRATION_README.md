# 異次元グルチャへの共有機能の統合

作成日：2026年11月11日。コード実装とローカル検証済み。本番公開・実機検証は未実施です。
同日、最新mainの歴史資料画像拡大・吉田松陰追加・プロフィール演出修正を保持して共有機能を合流しました。詳細は `MERGE_REPORT.md` を参照してください。

## 今回の動き

「異次元グルチャ」の今のトーク画面に、家族や友達が参加します。自分の発言は右側、他の人と偉人の発言は左側に、既存の描画処理で表示します。吹き出し・背景・トーク画面の配置を定義する既存CSSは変更していません。

- 共有を始めるときにメール認証します。通常の再起動ではログインと選択した部屋を復元します。認証期限切れやブラウザの保存削除時は再認証が必要です。
- 認証済みの人は自分の共有グルチャを1つ作成できます。他の人の部屋にも参加できます。従来から複数の部屋を持っている管理者の部屋は削除しません。
- 一覧の「家族・友達を招待」または参加者一覧の「招待」から、部屋の選択・管理ができます。
- 招待リンク→参加申請→管理者が承認→同じ画面で会話、という流れです。リンクの有効期限は7日です。
- 人間の投稿・偉人の投稿はSupabaseに保存します。同じ投稿順・同じ保存時刻を全員が参照します。各スマホの通信に応じ、表示の到着には差があります。
- トーク表示中は約1秒ごとに更新します。一覧表示中は約10秒ごとに更新します。入力中の表示は、配信予定の偉人の発言が15秒以内になったときに出します。
- 既読人数は実際に読んだ人間の参加者数です。架空の既読人数を追加しません。退会者は人数から除外します。
- 人間が発言すると未送信のAI会話を破棄し、新しい発言に返答します。返答用と自動会話用の生成を使い分けています。全員が同じAI回答を読みます。
- 人間が発言しない間は従来の偉人による会話をサーバーで準備します。アプリを閉じている間は定期実行が配信を進めます。
- 参加・退会のお知らせ、承認、管理者による退出処理、招待リンクの無効化、部屋名の変更、自動会話の停止、以前の会話の読み込みに対応します。
- 検索・引用・偉人のプロフィールは既存画面の機能を使います。検索対象は現在読み込んだ会話です。初回は直近100件、以前の会話は100件ずつ読み、画面上は最大500件を保持します。サーバーの古い会話は削除しません。
- 共有中は従来の個人用自動会話を止め、共有を終了すると戻します。個人用の会話は引き継がず、別に保存したままです。
- 学習履歴を話題にする連携は、この統合を有効にした環境では使用しません。学習履歴・教材・写真は削除しません。

## まず検証環境で導入

1. 最新mainに差分ZIPの同名ファイルを適用し、VercelのPreviewへデプロイします。公開中の生徒用環境に先に反映しないでください。
2. 検証用Supabaseを用意します。Supabase SQL Editorで `shared-chat/install_integrated.sql` を実行します。初期版・共有AI版の導入状態を自動判定し、必要な段階だけを1トランザクションで追加します。続いて `shared-chat/enable_integrated.sql` を実行します。
3. Previewだけに次の環境変数を設定して再デプロイします。キーは既存設定から引き継げますが、検証用SupabaseのURLとキーを組み合わせてください。

| 環境変数 | 値・用途 |
| --- | --- |
| `SHARED_CHAT_ENABLED` | `1` |
| `HIMIKO_SHARED_ENABLED` | `1`。今回追加した画面統合のスイッチ |
| `SHARED_CHAT_AI_ENABLED` | `1`。偉人の共有会話を有効化 |
| `SHARED_CHAT_SUPABASE_URL` | 検証用SupabaseのURL |
| `SHARED_CHAT_SUPABASE_ANON_KEY` | 同じプロジェクトのanonまたはpublishable key |
| `SHARED_CHAT_SUPABASE_SERVICE_ROLE_KEY` | 同じプロジェクトのservice_roleまたはsecret key。サーバー環境変数専用 |
| `ANTHROPIC_API_KEY` | 既存のAI用キー |
| `SHARED_CHAT_CRON_SECRET` | 24文字以上のランダムな秘密文字列。既存の`CRON_SECRET`でも代用可能 |

既存のRedis設定があれば、自動会話の話題の履歴と従来の利用制限に引き続き使用します。Redisがなければ、共有会話の話題選択は直近の投稿から重複を避ける方式になります。

4. Supabase Authのメール認証・メール送信を確認します。初期登録ができる設定、メール内に認証コードを表示するテンプレート、使用するドメインと送信元の設定が必要です。VercelのPreviewにアクセス制限をかけている場合は、検証するスマホと定期実行からアクセスできる状態にします。
5. GitHub ActionsのSecretsに `SHARED_CHAT_TICK_URL`（検証URLの`/api/shared-chat-tick`）と `SHARED_CHAT_TICK_SECRET`（上記の秘密文字列）を設定します。追加した「Shared Chat AI Scheduler」を手動実行し、その後は5分間隔の予定実行を確認します。GitHubの予定実行は遅延する場合があります。予定実行はmain上のワークフローが対象です。初回検証時は共有機能を無効にしたままワークフローをmainに置くか、外部スケジューラーから検証URLへPOSTしてください。
6. `.github`はMacで隠しフォルダになる場合があります。手動アップロード時はCommand＋Shift＋.で表示し、ワークフローの配置漏れに注意してください。

## 公開前にスマホ2台で確認

- Aがメール認証して部屋を作成。Bが招待リンクから認証・参加申請。承認前は読めず、承認後は同じ部屋に入れる。
- AとBが交互・同時に投稿し、相手のスマホにも同じ順序と時刻で表示される。再送しても二重にならない。
- 偉人の返答が実際の質問に合い、人物名と文章が両方で一致する。配信途中に質問すると、未送信の古い返答が混ざらない。
- 既読・未読線・入力中表示・参加者人数が更新される。別の学生の部屋は見えない。
- アプリを閉じて開き直してもログインと参加部屋が戻る。ネットワーク切断中の送信は入力を残し、復帰後に再送できる。
- 検索・引用・プロフィール・以前の会話を読む操作ができる。参加者の削除・退出後は会話が読めない。
- 元のトーク画面と並べ、吹き出しの形・幅・背景・送信欄・上下の配置・スクロールをiPhoneで確認する。
- 既存の学習進捗が残り、学習内容を偉人が勝手に話題にしない。

ここまで合格してから、本番へ差分とSQLをまとめて反映し、本番の3つの有効化フラグを設定して公開します。本番の定期実行URLも本番URLに変更します。既に001・002を実行済みでも、`install_integrated.sql`で導入できます。003を単独で実行した後に、もう一度003を実行しないでください。導入判定付きのinstallerは再実行を検証済みです。

## 利用回数と通知

AI呼び出しは初期設定で、1部屋あたり1日12回・全体で1日120回までです。日本時間の暦日で区切ります。自動会話5場面のまとめ生成も、質問への返答1場面も、それぞれ1回です。中断や失敗した呼び出しにも費用が発生し得るため、生成を予約した段階で回数を記録します。回数に達すると、その日の新しいAI生成を停止します。人間同士の送受信と、既に準備したAI発言の配信は続きます。人数に合わせて本番前に設定してください。上限は金額そのものの保証ではありません。

```sql
update shared_chat_private.settings
set room_daily_batches=12, global_daily_batches=120
where id=true;
```

通知は任意です。既存の `HIMIKO_VAPID_SUBJECT`、`HIMIKO_VAPID_PUBLIC_KEY`、`HIMIKO_VAPID_PRIVATE_KEY` が揃い、端末がWeb Pushに対応している場合に管理画面から有効にできます。iPhoneはホーム画面追加などのWeb Push条件を満たして検証してください。通知は定期実行に依存し、即時配信の保証はありません。

## 公開を戻す場合

`HIMIKO_SHARED_ENABLED=0` と `SHARED_CHAT_AI_ENABLED=0` にして再デプロイし、必要に応じて次を実行します。共有メッセージと学習履歴を削除する操作はありません。

```sql
update shared_chat_private.settings set integrated_enabled=false where id=true;
```
